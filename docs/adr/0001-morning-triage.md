# ADR-0001: 晨间处理流 (Morning Triage)

## 状态
已提议

## 背景
开发者每天早上需要：
1. 检查需要审查的 PR
2. 检查分配给自己的 Issue
3. 检查未读通知
4. 快速处理这些事项

当前问题：
- 需要打开多个浏览器标签
- 信息分散在 GitHub/GitLab/Jira
- 没有统一的待办视图

## 决策

实现 **Morning Triage** 功能：

1. **聚合队列**: 从所有数据源收集"需要我处理"的事项
2. **优先级排序**: 按紧急程度自动排序
3. **快捷操作**: 在 Dashboard 内直接处理
4. **键盘导航**: 支持快捷键快速处理

## 具体设计

### 数据源覆盖

| 数据源 | 待办类型 | API 查询 |
|--------|----------|----------|
| GitHub | 审查请求 | `review-requested:@me` |
| GitHub | 分配的 Issue | `assignee:@me` |
| GitHub | 未读通知 | `/notifications` |
| GitLab | 审查请求 | `/merge_requests?scope=assigned_to_me` |
| Jira | 分配的任务 | `assignee = currentUser()` |
| Linear | 分配的问题 | `issues(filter: { assignee: { id: { eq: me } } })` |

### 优先级规则

1. **P0 - 紧急**: CI 失败 + 需要你审查
2. **P1 - 重要**: 审查请求等待 > 24h
3. **P2 - 普通**: 分配的 Issue 即将到期
4. **P3 - 低优先级**: 其他未读

### 快捷操作

| 操作 | 快捷键 | 说明 |
|------|--------|------|
| 批准 | A | 批准 PR |
| 请求修改 | R | 请求修改 |
| 合并 | M | 合并 PR |
| 关闭 | C | 关闭 Issue/PR |
| 跳过 | S | 标记为已读/稍后处理 |
| 打开 | O | 在浏览器打开 |

## 后果

### 正面
- 减少上下文切换
- 提高晨间效率
- 统一跨平台工作流

### 负面
- 需要维护更多 API 集成
- 快捷操作需要谨慎设计（避免误操作）

## 替代方案

1. **只做展示**: 不实现快捷操作，只聚合展示。拒绝：操作路径仍然太长。
2. **浏览器扩展**: 在 GitHub 页面内实现。拒绝：无法跨平台。
